01 / Objective

Finish expressions and every grammar family that calls back into them

The existing parser already owns statements, declarations, delimiters, scopes, recovery, and typed deferred children. Phase 04 supplies expressions, type names, initializers, and expression-dependent declaration children while preserving that protocol: one control stack, one delimiter owner, typed reductions, exact provenance, and bounded recovery.

Design revision: the language and preprocessor expression parsers intentionally keep independent reducer implementations. Do not add a shared reducer module; src/translation_phases/ contains only C translation phases.

Phase 04 owns

  • Primary through comma expressions.
  • Type names for casts, sizeof, and compound literals.
  • Scalar, braced, nested, and designated initializers.
  • Every statement and declaration future child.
  • Parser-local precedence reduction owned by ExpressionFrame.

Phase 05 closes the parser

  • Audit the complete C99 grammar matrix.
  • Harden cross-family recovery and limits.
  • Close omissions found by the audit.
  • No planned grammar-family handoff.

Later semantic work

  • Type resolution and conversions.
  • Lvalues, member lookup, and call checking.
  • Constant evaluation and sequence analysis.
  • Initializer current-object, brace-elision, and override rules.
  • Backend lowering and extensions.
Merged cluster: ExpressionFrame pushes type names and compound-literal initializers; InitializerFrame pushes assignment and constant expressions; declarator, struct, enum, and declaration frames push the same expression/initializer entry modes. Phase 04 lands and verifies that full cycle.
02 / Baseline

Build from the Phase 03 machine that actually exists

Implemented foundation

  • Parser owns a buffered cursor, control frames, arenas, scopes, recovery, and diagnostics.
  • DeclaratorFrame(Abstract) already handles abstract pointer, grouping, array, and function shapes.
  • ScopeStack publishes and shadows typedef names at parser-visible token positions.
  • Statements and declarations expose typed future-child seams with parent-owned delimiters.

Model and reachability gaps

  • ParseFrame and ParseValue have no expression, type-name, or initializer variants.
  • Expression/type-name storage is incomplete; initializer/designator arena storage is absent.
  • Calls and initializer lists need stable child slices; malformed children need typed recovery nodes.
  • The preprocessor has an independent reducer implementation that Phase 04 leaves unchanged.

04 / Architecture

One parser driver with expression reduction owned by its frame

Input and control

Parser driver

Buffered typed tokens, Vec<ParseFrame>, typed child return, recovery state, scopes, and arenas.

→
Parser-local mechanism

ExpressionFrame reduction

Operand/operator state, stacks, precedence, associativity, blocking markers, provenance, and progress invariants.

↔
Typed child grammar

Type names / initializers

The language parser pushes typed child frames and constructs expression handles and source-backed syntax.

enum ParseFrame {
    // Phase 03 frames...
    TypeName(TypeNameFrame),
    Expression(ExpressionFrame),
    Initializer(InitializerFrame),
}

enum ParseValue {
    // Phase 03 values...
    TypeName(TypeNameIndex),
    Expression(ExpressionResult),
    ConstantExpression(ConstantExpressionResult),
    Initializer(InitializerResult),
}

ExpressionFrame owns

  • Entry mode and caller stop set.
  • Operator stack with provenance and blocking markers.
  • Operand handles plus assignment-left grammar category.
  • Arguments, type-name waits, initializer children, and recovery.

The preprocessor remains separate

  • It retains its own operand/operator stacks and state.
  • It retains integer evaluation and short-circuit bookkeeping.
  • It retains extension policy and diagnostic wording.
  • No cross-phase reducer module is added under src/translation_phases/.
InitializerFrame owns: scalar-versus-braced selection, nested list state, list commas and braces, optional designation chains, field and array designators, expression children, and recovery before its caller's delimiter.
05 / Syntax model

Store the mutually recursive grammar behind stable typed handles

Type names

Add TypeNameIndex. Casts, sizeof, and compound literals refer to the type-name arena instead of cloning inline values.

Expressions and initializers

Calls use stable ExpressionIndex slices. Initializers use InitializerIndex plus ordered element, designation, and designator storage.

Recovery

Add recovered/error expressions and initializers. Remove every final FutureChild; retain Missing only for truly absent required syntax.

Typedef decision: after ( in operand state, a type keyword/qualifier or currently visible typedef name starts TypeNameFrame; otherwise parse a grouped expression. If any implementation tentatively parses, it must roll back cursor, arenas, reducer stacks, diagnostics, and scope state before trying the alternative.
06 / Delivery

Land vertical slices with a checkable exit at every step

  1. Freeze the baseline and grammar matrix

    Characterize every future-child site, operator/initializer form, entry mode, ambiguity, stop token, malformed state, and preprocessor behavior.

    ExitEvery Phase 04 grammar and recovery row has a named test and owner; the 137-test baseline is locked.
  2. Repair syntax and arena storage

    Add stable type-name, expression, initializer, element, designation, designator, and child-list storage with recovery/provenance forms.

    ExitEvery in-scope form is losslessly representable and no final AST form requires FutureChild.
  3. Implement private language-expression reduction

    Keep operand/operator stacks, state, precedence, associativity, markers, provenance, and progress rules directly in ExpressionFrame; do not change preprocessing.

    ExitThe public parser operator matrix passes and the independent preprocessor suite remains green.
  4. Implement TypeNameFrame

    Compose specifier-qualifier parsing with optional abstract declarators; preserve prototype scope and a typed within-phase array-bound contract.

    ExitExpression-independent type names return source-backed handles without recursion or identifier-bearing declarators.
  5. Parse primary and postfix expressions

    Land identifiers, constants, strings, grouping, subscripts, calls, member access, and postfix increments/decrements through real statement paths.

    ExitPostfix chains compose; f(a,b) and f((a,b)) have different argument shapes.
  6. Parse unary, casts, and sizeof

    Preserve the asymmetric unary/cast grammar and push type-name children only after current-scope typedef classification selects them.

    ExitChained casts, both sizeof forms, grouping, and scope shadowing choose the correct syntax.
  7. Complete infix and comma reduction

    Add every binary level, nested conditional handling, all assignments, comma, and operand grammar categories for assignment-left syntax.

    ExitThe operator matrix and all associativity/comma contexts produce exact ASTs or focused diagnostics.
  8. Parse scalar and brace initializers

    Implement assignment-expression initializers and iterative nested initializer lists with owned braces, commas, and optional trailing comma.

    ExitScalar and nested list initializers produce stable handles; malformed children retain list shape.
  9. Parse designations and designators

    Parse ordered field/array designator chains, constant-expression indices, member identifiers, required =, and the designated initializer.

    ExitChained and mixed designations recover without stealing element or list delimiters.
  10. Build compound literals

    Delay cast reduction through lookahead, push the real initializer frame, store its handle, and resume postfix parsing.

    ExitEvery compound literal has parsed type-name and initializer handles; following postfix syntax composes.
  11. Replace Phase 03 expression seams

    Connect expression statements, selection/iteration controls, all for slots, returns, and case labels while preserving statement delimiters.

    ExitEvery valid present statement expression is parsed; StatementExpressionNotImplemented is gone.
  12. Replace declaration-side seams

    Connect array bounds, bit-field widths, enumerator values, and declaration initializers with correct entry modes, publication timing, and parent delimiters.

    ExitAll declaration-dependent positions contain parsed handles; unsupported diagnostics are gone from valid paths.
  13. Harden recovery and limits

    Cover every expression/type-name/initializer/designator/EOF state, later-item continuation, 63 nested parentheses, 127 arguments, and deep initializer lists.

    ExitAll paths terminate with balanced reducer/frame/scope state and no caller delimiter theft.
  14. Verify, document, and hand off

    Run canonical checks, inspect all syntax families via the CLI, update status/compliance guidance, and hand only closure/audit work to Phase 05.

    ExitTests and formatting pass; changed files are Clippy-clean; no supported future-child path remains.
