01 / Decision

Phase 02 is migration work, not a synthetic kernel.

The older roadmap separated the machine kernel from declaration migration. This plan combines them: the kernel earns its place immediately by carrying existing parser behavior.

Core rule

Port a path. Prove it. Delete the old path.

Each increment must be reachable through Parser::next_item. Tests cross the same parser interface as callers; private frames are implementation detail.

  • One control flow. No permanent legacy fallback.
  • Owned actions. Frames never retain machine borrows.
  • One delimiter owner. Token use is traceable.
  • Green replacement. Characterize before moving.
  • Sharing later. The preprocessor remains untouched.

03 / Architecture

One driver, specialized resumable frames.

The stack machine replaces recursive grammar calls. It does not turn the entire C grammar into one operator stack.

Input

TokenCursor

Owns lookahead, consumption, and explicit reprocessing.

  • Current token or EOF
  • Caller delimiters survive
  • No scattered pushback
→
Control

Parser + frame stack

Drives owned actions until one external declaration or EOF is produced.

  • Consume
  • Push child
  • Reduce value
  • Reprocess
  • Recover
→
State + output

SyntaxStore + ScopeStack

Owns AST arenas, source provenance, file-scope name classes, and diagnostics.

enum ParseAction {
    Consume,
    Push(ParseFrame),
    Reduce(ParseValue),
    Reprocess,
    Recover(SynchronizationSet),
}

Borrowing rule

A frame returns an owned action. The driver applies it only after the frame borrow ends, so cursor, stack, stores, scopes, and diagnostics can change safely.

04 / Scope

Move what exists; preserve the next child seam.

Phase 02 ports expression-independent declaration grammar. Missing child grammars receive an explicit typed handoff and deterministic recovery—not a call into a stub.

Migrates now

Existing declaration machinery

  • External and ordinary declaration entry
  • Storage, type, qualifier, and function specifiers
  • Pointer, direct, parenthesized, array, function, abstract, and K&R declarators
  • Parameter lists and variadics
  • Struct, union, and enum forms independent of expressions
  • File-scope typedef and ordinary-name classification
  • Arenas, diagnostics, provenance, and recovery
Typed future children

Implemented in later phases

  • Array-bound expressions
  • Bit-field widths and explicit enum values
  • Initializers
  • Function definitions and bodies
  • Expressions and statements
  • Nested scopes and full redeclaration constraints
  • Semantic analysis

Port struct, union, and enum specifiers

  • Named and anonymous bodies
  • Nested tags
  • Member lists
  • Trailing enum comma

  • Correct struct vs union kind
  • Correct enumerator slice arena
  • Future constant-expression children
Gate: all expression-independent tag branches are frame-driven and both defects are green.
Delete: old struct, union, enum, and identifier helper methods.
6

Remove legacy control flow

Close the compile gate by deleting incomplete paths and retaining only explicit future grammar phases.

Remove
  • Empty State enum
  • Obsolete pushback helpers
  • Unused expression/statement entry stubs
  • Incomplete declaration/function flow

  • No fallback to legacy code
  • Remaining grammar gaps are typed
  • cargo check passes
Gate: one control-flow implementation remains and the crate builds.
7

Verify, document, and hand off

Run the full matrix, stress the frame stack, and make current-versus-future scope explicit in project docs.

Gate: checks are green, migrated/deferred branches are listed, and the handoff contains evidence.
