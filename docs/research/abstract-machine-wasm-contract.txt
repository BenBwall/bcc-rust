CHOICE / COORDINATION FOR ENGINE AGENT
Cargo features: default=[native] preserves the existing compiler; the independent
abstract-machine feature enables src/abstract_machine.rs without native compiler
modules or dependencies. Build with cargo rustc --no-default-features --features abstract-machine
--lib --crate-type cdylib --target wasm32-unknown-unknown. Explicit crate type
keeps the native default artifact behavior unchanged.
The native parser cannot be included with minimal cfg changes: its 100 GiB
GrowingRegion reservations overflow wasm32, vm.rs implements only OS/Miri
reservation APIs, binary128 and float parsing require generated native FFI, and
build_support/native.rs requires TARGET=HOST and LLVM cross-language LTO.
A wasm allocator would need bounded fixed regions (linear-memory growth cannot
relocate live references), resource/include policy, and float conversion work.
No broad allocator rewrite is planned. ENGINE: implement a self-contained,
honestly bounded C subset using std, without importing crate native modules.
Native real-parser integration can remain a future seam.

RUST ENGINE INTERFACE (adapted to the engine agent's actual API):
  abstract_machine::compile(source: &str) -> Result<Program, Diagnostic>
  Program::session(&self) -> Session
  Session::{state_json,trace_json} -> String
  Session::{step,back} (return values ignored by bridge)
  State::to_json(&self) -> String
Bridge retains Program for reset and reconstructs its initial Session. No
Session::compile or Session::reset adapter is required in engine-owned files.
Rejected source returns an engine-shaped status=error state with diagnostics;
compile still returns ABI dispatch success (0). Previous session is discarded.
State/trace JSON schema is engine-owned; UI should read actual model/json files.

RAW WASM ABI (no wasm-bindgen, no imports, one session per wasm instance):
  memory: exported WebAssembly.Memory
  bcc_abi_version() -> u32 = 1
  bcc_alloc(len: u32) -> u32  (zero-initialized input; 0 on invalid/too-large request)
  bcc_free(ptr: u32, len: u32) (same pointer and length from alloc; free exactly once)
  bcc_compile(ptr: u32, len: u32) -> u32
  bcc_state() -> u32
  bcc_step() -> u32
  bcc_back() -> u32
  bcc_reset() -> u32
  bcc_trace() -> u32
  bcc_response_ptr() -> u32
  bcc_response_len() -> u32
All operation exports return 0 on successful dispatch, 1 for invalid UTF-8/input
or missing session. C compile diagnostics are a successful dispatch (see JSON).
Response bytes are UTF-8 JSON owned by wasm, valid until the next operation.
Use fresh Uint8Array(memory.buffer, ptr, len) after every call: allocation/step
may grow memory and detach previous views. Copy/decode a response before calling
another operation. Input remains caller-owned; compile copies/parses it before
returning, then JS calls free. No calls are reentrant. Instance is single-threaded.
Input limit: 1 MiB. Bounds/UTF-8 checked by compile; alloc/free are a C ABI requiring
correct ownership and pairing. Invalid free is caller error, as in C.
Transport failures return {"version":1,"error":"..."}.
