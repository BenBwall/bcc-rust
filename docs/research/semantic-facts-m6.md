# M6 builtin families in the registry

Base: `codex/issue-swarm` at `66a4f7b5`, which is PR #72's head plus local fixes,
containing M1-M5, atomic execution (`39990b8e`), real math contracts
(`b52465ec`), checked/fortify builtins and overload/tgmath. Branch
`claude/semantic-facts-m6`. This implements migration row M6 of
[the design](../design/semantic-facts.md) and inventory rows B04-B06, B10,
B12, B13, B22 and B26. Completion is recorded in
[semantic-analysis.md](../../semantic-analysis.md) ("Builtin families in the
registry") and [middle-end.md](../../middle-end.md).

## Result and choices

Every builtin spelling and keyword form now has exactly one descriptor in
`src/builtins/`. The registry grows from 369 to 775 descriptors:

| Shard | Descriptors | Source |
| --- | ---: | --- |
| scalar, library, math, checked | 305 | unchanged (M4, PR #72) |
| atomic | 64 | unchanged (PR #72 already registered the atomics) |
| `x86.rs` | 384 | generated by `scripts/generate_x86_builtins.py` |
| `vector.rs` | 12 | handwritten |
| `type_generic.rs` | 10 | handwritten |

Keyword forms (`types_compatible_p`, `choose_expr`, `convertvector`,
`bit_cast`) join `va_arg`/`offsetof` as descriptors reached through
`registry::keyword_descriptor`, the adapter from the one keyword classifier.
PR #72's atomics, math contracts and checked builtins were already registry
shards at the base, so M6 only removed the atomic name predicate
(`atomics::modeled`/`intrinsic`); `atomic_call` now receives its
`AtomicBuiltin` from the descriptor. tgmath has no builtin; overloadable
functions are ordinary user declarations and stay outside the registry.

Deleted:

- `semantic_analysis/builtins/names.rs` (the `named_builtin` /
  `legacy_named_builtin` union) and `BindingOrigin::LegacyIntrinsic`;
- `semantic_analysis/builtins/x86_builtin_table.rs` (407 lines) with
  `x86_builtins::known`, `x86_builtin_type` and `x86_builtin_operand`;
- `vectors::named_builtin`, `type_generic::named_builtin`, `atomics::modeled`
  and `atomics::intrinsic`;
- the spelling tables inside `vector_overload` and `math128_builtin`, the
  keyword `matches!` list in `builtins::modeled`, and the `implemented_builtin`
  and `named_builtin` re-exports that preprocessing called.

Choices made within M6:

- **Closed family rules, dedicated handlers.** `TypeRule` gains
  `X86Signature`, `VectorShuffle`, `VectorOverload(VectorOverload)`,
  `ConvertVector`, `BitCast`, `TypesCompatible`, `ChooseExpr`, `TypeClassify`
  and `Math128(Math128)`. `common_builtin_call` is the single named-call entry
  and dispatches on the binding descriptor's rule; `type_builtin` does the same
  for keyword forms. The shuffle, overload, classification, binary128, type
  compatibility, selection, conversion and bit-cast algorithms are unchanged.
- **x86 signatures and immediates as descriptor data.** `SignatureType` gains
  `Vector(Scalar, lanes)`, `VectorPointer(Scalar, lanes, const)` and `Opaque`.
  Each x86 operand is an `ArgumentRule` with `ConversionRule::Prototype`; an
  immediate carries `ConstantConstraint::Immediate(low, high, mask)` and the
  `ConstraintDiagnostic::Immediate` identity (projected to `InvalidImmediate`).
  `x86_immediates` reads them after prototype conversion as before. The
  feature diagnostic keeps its `x86 builtin` text when a call first binds the
  spelling.
- **Merged scalar spellings.** The generator's discovery includes
  `__builtin_popcount` and `__builtin_popcountll`. It now emits them into a
  test-only `MERGED` table instead of a second descriptor, and
  `m6_merged_x86_spellings_agree_with_their_scalar_descriptor` checks that the
  scalar descriptors have the Clang-verified signatures. A spelling has one ID.
- **No instances for family operations.** Family operations are
  `BuiltinOperation::Semantic(ClassifyType | TypesCompatible | ChooseExpr |
  Math128)` or `Unsupported(X86 | Vector)`, with `BuiltinEffectClass::Unknown`.
  `BuiltinOperation::retains_instance` is false for both. Semantic analysis
  therefore retains no `BuiltinCallFacts` for them, M5's effect summary of
  such a call stays `UNKNOWN`, and lowering's `schedule_builtin` lets the call
  reach the unchanged unsupported-builtin refusal (a descriptor without an
  instance is a `MissingFact` only when its operation retains one).
- **Opaque bindings preserved.** Families without a single C type use the
  `Opaque` signature, which projects to the same unprototyped unknown-result
  function the old fallback built. A keyword form's spelling that is an
  identifier because `classify` disables its keyword in a configuration is not
  bound to the keyword descriptor and stays an opaque reserved name, as
  before.
- **`__has_builtin` reads the registry.** `language_features::has_builtin` no
  longer calls semantic analysis: a keyword form is advertised where
  `KeywordTokenType::classify` makes its spelling a keyword, an ordinary call
  by naming policy (reserved always, Microsoft with Microsoft compatibility,
  plain GNU `alloca` never).
- **One deliberate visible change.** Sixteen spellings were modeled by a
  handler but missing from the old union, so `__has_builtin` answered 0 for
  them: `__builtin_elementwise_{abs,sqrt,add_sat,sub_sat,min,max}`,
  `__builtin_nondeterministic_value`, `__builtin_nontemporal_{load,store}`,
  `__builtin_nans` and `__builtin_{huge_val,inf,nan,nans,fabs,copysign}f128`.
  They now answer 1, as the design's "advertise modeled semantics" rule and
  GCC/Clang do. Their binding types and call diagnostics are unchanged.
- **Lowering keyword scheduling kept.** `schedule_keyword` still matches the
  varargs/offsetof/`choose_expr` keywords: the existing provenance test removes
  a keyword instance and expects `MissingFact`, which a facts-only dispatch
  cannot distinguish from a family form. Its comment now describes this as
  syntax scheduling rather than an M6 bridge.

## Coverage and validation

**Old-versus-new name comparison.** `6aa50fe8` adds
`builtin_names_match_the_recognition_snapshot` and blesses
`tests/fixtures/semantic/builtin-names.snap` from the unmodified base. Its
candidates are the registry, the old x86 table, the families outside the
registry, the builtin keywords and unknown probes (`__builtin_M6_unknown`,
`__builtin_ia32_M6_unknown`, `__atomic_M6_unknown`, `__sync_M6_unknown`,
`__builtin_tgmath`, `__cpuidex`, `alloca`): 781 spellings. Each row records the
`__has_builtin` answer under strict C17, GNU, C99 with extensions denied and
MSVC compatibility, and, for a non-keyword, the origin class and spelled type
of the binding an undeclared call creates and the diagnostics of a call with
no arguments. After the switch the test was run before reblessing: exactly 16
rows differed, each only in its `__has_builtin` bits (the spellings listed
above). Every binding type, origin class and diagnostic list was identical.
The snapshot reads its own names back, so a later change cannot drop one.

**Generated x86 data.** `scripts/generate_x86_builtins.py` was rerun with the
pinned Clang 23.1.1 (`target/llvm/bin/clang`): it verified all 386 header-call
signatures on the four targets (empty stderr on each triple) and emitted 384
descriptors plus 2 merged spellings. A script comparison decoded every emitted
descriptor back into the old encoding: all 384 signatures and immediate lists
(111 descriptors with immediates) equal the deleted table, and both merged
encodings match. The generator now finds Clang as `clang` or `clang.exe` and
emits the shard; `scripts/generate_builtin_index.py` reads the three new shards
and appended IDs 369-774 without renumbering any existing ID (the regenerated
`index.rs` diff is insertions only).

New registry tests:

- `m6_family_descriptors_retain_no_instance_and_keep_their_contracts`: every
  family descriptor is `Semantic`/`Unsupported` and retains no instance; x86
  descriptors are prototyped with one argument rule per parameter (384, 111
  with immediates); keyword family forms have keyword syntax.
- `m6_merged_x86_spellings_agree_with_their_scalar_descriptor`.
- `m6_every_resource_header_builtin_is_registered`: every `__builtin_`,
  `__atomic_` and `__sync_` identifier in `src/headers/**/*.h` is registered.
- `m6_x86_signatures_project_identically_on_every_target`: all 384 bindings
  spell identically on the four targets, and every vector is sized as its
  alignment.
- `lowering::tests::registry::m6_family_calls_remain_unsupported_builtins`: in
  lowerable units an x86 call (`__builtin_ia32_crc32si`) fails only with
  `Unsupported(Builtin)`, and an overload (`__builtin_nontemporal_load`) and a
  non-constant binary128 primitive (`__builtin_nans(tag)`), whose bindings keep
  their pre-M6 opaque type, only with `UnanalyzedType`; all with provenance.
  Its first run caught a second consumer, `lowering/address_taken.rs`, that
  still reported `MissingFact` for any intrinsic with a descriptor but no
  instance; it now applies `retains_instance` like `schedule_builtin`.

The M4 registry tests now cover all 775 IDs (spelling round trip, suffix
probes, `__has_builtin` on four targets in strict/GNU and hosted/freestanding
modes, user function-pointer shadowing of every ordinary spelling). The
existing atomic order-warning and lock-free fold tests
(`semantic_analysis/tests/atomics.rs`, `pipeline/tests/middle_end/atomics.rs`),
vector lane/type tests (`tests/vectors.rs` and its fixtures), binary128 and
type-generic tests (`tests/float128.rs`, `tests/type_generic.rs`), and the IR,
diagnostic, `--semantic-types` and registry inspection goldens pass without
reblessing.

## Residual items for M7 and later

- Reserved builtin type names (`__builtin_va_list`, `__int128_t`,
  `__uint128_t`) still have no `BuiltinTypeDescriptor`; `declarations.rs`
  recognizes them itself (inventory B30).
- Lowering's `schedule_keyword` still matches keyword kinds. Retaining the
  keyword descriptor ID in `Callee::Builtin` would let it dispatch on facts.
- Family calls keep `UNKNOWN` effects and no normalized operands; retaining
  instances for x86/vector operations belongs with their lowering.
- `semantic_analysis/builtins/x86_builtins.rs` also hosts the vector overload
  handler; moving it beside `vectors.rs` would match its registry shard.
- `builtin_name` still treats every undeclared `__builtin_*` identifier as an
  opaque reserved name; unknown reserved names remain `OpaqueIntrinsic`.
- Matched GCC torture survey for M6 (above).
