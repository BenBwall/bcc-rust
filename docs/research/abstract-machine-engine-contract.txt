Bounded C execution API and schema v5

CHOICE: independent, explicitly bounded C subset evaluator. No compiler/LLVM,
filesystem, virtual-memory arena, serde, wasm-bindgen, or other dependencies.
The native frontend was evaluated: pipeline::parse_translation_unit and
analyze_translation_unit expose the right syntax/semantic inputs for a future
adapter, but retain Context/Bump/RegionVec and native compiler dependencies.
This prototype must NOT be labelled as executing bcc's full C frontend.

The `abstract-machine` feature exposes `pub mod abstract_machine`. The module
requires only std and builds on native and wasm32. `abstract_machine_wasm.rs`
wraps the safe Rust API; the engine defines no raw exports.

PUBLIC API:
  pub const DEMO_SOURCE: &str;
  pub fn compile(source: &str) -> Result<Program, Diagnostic>;
  Program::session(&self) -> Session;
  Program::source(&self) -> &str;
  Session::step(&mut self) -> &State;
  Session::back(&mut self) -> &State;
  Session::state(&self) -> &State;
  Session::state_json(&self) -> String;
  Session::trace_json(&self) -> String;
  Program::writes_output(&self) -> bool;
  Diagnostic::to_json(&self) -> String;
No unsafe ABI in engine; wrapper can hold Session and return JSON bytes.

JSON schema v5 (v1 fields shown; later versions add the event, evaluation
and structure fields, objects' storage_duration "static", function, parameter
and literal, and the state's output and written; v5 adds the diagnostic kind
"constraint"):
  {schema_version:5, engine:"bounded-c-subset", step:number,
   status:"ready"|"running"|"finished"|"undefined_behavior"|"error"|"limit",
   source_range:{start:byteOffset,end:exclusiveByteOffset,line:oneBased,
                 column:oneBased,end_line:oneBased,end_column:oneBased},
   event:string, frames:[{id:number,function:string,depth:number}],
   objects:[{id:number,name:string,type:string,frame_id:number,
             storage_duration:"automatic",lifetime:"alive"|"ended",
             value:Value, literal:boolean}], pending_effects:[string],
   diagnostics:[Diagnostic], return_value:null|Value,
   output:string, written:number}
  output is everything written to standard output so far (bytes that are not
  UTF-8 become replacement characters in JSON; State::output keeps the
  bytes), written how many bytes at its end the last step wrote.
  Value = {kind:"indeterminate"} | {kind:"integer",value:number}
        | {kind:"pointer",target:number|null,offset:number}
        | {kind:"array",elements:[Value]}
  Diagnostic = {kind:"unsupported"|"syntax"|"constraint"|"undefined_behavior"
                     |"indeterminate"|"limit",
                message:string,source_range:Range,citation:string|null}
  "constraint" is a compile-time violation of a C99 constraint, which every
  compiler must diagnose (5.1.1.3p1): the program is not valid C, as opposed
  to "unsupported", valid C outside the subset.
Pointer offsets are int elements, never host addresses. Object IDs never reused.
source_range is the next operation; event describes the last completed step.
Trace JSON: {schema_version:5,source:string,structures:[...],states:[State,...]}.
Back restores a recorded complete machine state; forward replays existing states.

Subset: signed 32-bit int, plain char (signed, 8 bits), pointers to int and
char (and to const int and const char), fixed int and char arrays, const int
and const char objects and arrays, structures and pointers to them,
file-scope and block-scope static objects, int- or structure-returning named
functions with named parameters of those types, prototypes declared before
their definitions, block locals/scopes, if/else, while, for, return,
assignments, arithmetic/comparisons, address/dereference/subscript/member,
casts between int and char and between pointers that differ only in const,
prefix/postfix increment and the compound assignments += -= *= /= %= as
standalone statements. Array and structure brace initialization; char arrays
also from a string literal, with or without a size. Character constants and
string literals with the simple, octal and hexadecimal escapes; adjacent
string literals are joined (translation phase 6). At file scope, `#include
<stdio.h>` and object-like `#define NAME replacement` whose replacement is one
decimal integer constant, character constant or string literal, each run by
the machine as one step of translation phase 4, and the calls printf, puts
and putchar. printf takes %d %i %u %x %c %s %% with the - and 0 flags, a
decimal field width and a decimal precision. No other directive (function-like
macros, #if, #undef, ...), header or library function, no floating point,
unsigned or long types (so no cast to them), malloc, function pointers,
arbitrary declarators (const pointers `* const`, const parameters and
members), wide literals, or compound side-effect expressions. Unsupported
input is an explicit diagnostic, never scripted or ignored.
Evaluation order: chosen left-to-right for side-effect-free operands; calls
are allowed as a whole scalar initializer/RHS/return/condition/expression
statement. Calls in array initializer lists and nested calls are rejected.
Assignments/increments nested in expressions are rejected to avoid claiming
unimplemented C99 sequencing checks. pending_effects describes the next store;
this prototype does not model deferred/unsequenced writes.

Bounds: source <=32 KiB; parser nesting <=64; code <=8192 operations;
runtime <=2048 steps, <=32 frames, <=128 total objects (string literals
included), <=512 scalar cells, <=1024 operands; a string literal holds <=511
characters (after joining), a library call <=16 arguments, a printf field
width and precision <=256 each, and
standard output <=4096 bytes; recorded states stop at an 8 MiB conservative
retention threshold (output included; plus one bounded terminal state and
vector capacity overhead). Limits are explicit terminal diagnostics, not UB or
silent truncation.

IMPLEMENTATION NOTES:
- Session snapshots retain the complete operand/call/scope/object state, rather
  than recomputing execution on back/forward. IDs are activation/allocation IDs.
- Indeterminate reads (including pointers whose targets have ended) stop with
  kind "indeterminate", status "error" and a verified rule. This is a
  conservative prototype policy, not a claim that every such read is UB.
- UB checks: checked signed int arithmetic, division/remainder by zero,
  invalid/null/one-past dereference, pointer arithmetic outside the target,
  a store into a string literal's array (6.4.5p6), and for the library calls
  a null pointer where a string is needed (7.1.4p1), a string with no null
  before the end of its array (7.1.1p1, 7.19.6.1p8), a conversion with no
  argument left (7.19.6.1p2), an argument of the wrong type for its
  conversion, a negative int for %u or %x, an invalid specification, the 0
  flag with %c or %s (7.19.6.1p6, p9), and a precision with %c (7.19.6.1p4);
  a store into an object defined const through an lvalue that is not, which
  only a cast that removed the const can form (6.7.3p5).
- Directives run before the static objects are created, one step each; the
  machine runs only `#include <stdio.h>`, which must come before the first
  call to printf, puts or putchar (7.1.2p4), and object-like `#define`. Every
  other directive, a #define with any other replacement list, and a directive
  inside a function, is rejected; the site then shows its "machine starts
  after the preprocessor" card. A redefinition with a different replacement
  is a constraint diagnostic (6.10.3p2); an identical one is a step that
  changes nothing.
- A #define replaces each later instance of its name before compilation
  (6.10.3p9), so the program the machine compiles never mentions it. Each
  operation that evaluates a replacement (a constant, a character constant,
  a string literal's array) is marked with its macro and narrated as the
  replacement standing in for the name, citing 6.10.3p9; a macro in an array
  size or a static initializer is noted on that declaration's step. The
  replacement is checked where it is defined.
- Adjacent string literals become one literal after escape replacement
  (5.1.1.2p1 item 6, 6.4.5p4), so "\x4" "1" is two characters: one static
  array named by the literals as written, separated by one space, whose
  creation step says they were joined.
- const objects: assignment, compound assignment, ++ and -- on a const object
  or through a pointer to const are constraint diagnostics (6.5.16p2,
  6.5.2.4p1, 6.5.3.1p1), and so is storing a pointer to const into a pointer
  to non-const (6.5.16.1p1). A const object's type is spelled "const int" or
  "const char". A const array decays to a pointer to const.
- A cast is one step converting its operand: an int that fits in char, or a
  char to int, keeps its value (6.3.1.3p1); an int outside -128..127 cast to
  char wraps modulo 256, the implementation-defined result bcc and GCC give
  (6.3.1.3p3); a cast to the operand's own type changes nothing (6.5.4p4);
  between pointers it adds or removes const. Casts to other types, between
  integers and pointers, and between different pointer types are
  unsupported; a cast of a structure is a constraint diagnostic (6.5.4p2).
- `E1 op= E2` designates E1 in one step, evaluates E2, and in one step reads
  E1, applies op with the plain operator's checks and stores the result
  converted to E1's type (6.5.16.2p3); its operands follow 6.5.16.2p1-2.
- printf precision is the minimum number of digits for %d %i %u %x (a zero
  with precision 0 writes nothing) and the maximum number of characters %s
  writes, which then needs no null within that many (7.19.6.1p4, p8); with
  a precision the 0 flag is ignored (7.19.6.1p6).
- Each string literal in the source is its own unnamed char array of static
  storage duration, named by its spelling, created before main in source
  order. A literal that initializes a char array names no object: its
  characters initialize the array in one step (6.7.8p14).
- A library call is one step: it reads its strings element by element with
  the ordinary lifetime, bounds and indeterminate checks, writes to standard
  output and returns what C says (printf the count written, putchar the
  character as an unsigned char, puts a nonnegative value: the count written,
  as glibc returns). A char passed through printf's `...` gets the default
  argument promotions as a step of its own. Valid printf specifications the
  machine does not model (*, length modifiers, other flags and conversions)
  stop as unsupported, not UB.
- &*p and &array[n] cancel indirection per C99 6.5.3.2p3, allowing formation
  of a one-past pointer without treating it as a read.
- Syntax, type and call-arity checks run for all parsed code, including dead
  branches. Unknown names/callees, incompatible pointer/int assignments,
  nested writes/calls, and unsupported preprocessing transformations fail.
  Constraint checks (const, compound-assignment operands, casts) run there
  too, so a program that breaks one never starts.
- Non-main fallthrough is conservatively unsupported even if a caller would
  discard the value. Main fallthrough returns zero. Array tails initialize zero.
- Pending effects describe the imminent store/increment; there is no deferred
  side-effect queue, exhaustive order exploration, or whole-C UB certification.
- No engine ABI exports; the wasm bridge wraps this safe API.
- Calls require the current function, an earlier definition or an earlier
  prototype (self-recursion works). Every declaration of a function must give
  it the same return and parameter types (6.7.5.3p15); a prototype with empty
  parentheses, a call to a function declared but never defined, and an
  unnamed parameter in a definition are rejected. A const char * may not be
  stored into a char *, and a char reached through one may not be modified.
- Standalone (*p)++/(*p)-- and ++*p/--*p update the pointed-to int. Bare *p++
  and *p-- are rejected as nested effects, preserving C postfix precedence.

Automatic lifetimes begin at declarations in this prototype. C99 fixed
automatic objects instead begin lifetime at block entry (6.2.4p5); initialization
happens when the declaration is reached. This approximation is visible in the UI.
