Bounded C execution API and schema v7

CHOICE: independent, explicitly bounded C subset evaluator. No compiler/LLVM,
filesystem, virtual-memory arena, serde, wasm-bindgen, or other dependencies.
The native frontend was evaluated: pipeline::parse_translation_unit and
analyze_translation_unit expose the right syntax/semantic inputs for a future
adapter, but retain Context/Bump/RegionVec and native compiler dependencies.
This prototype must NOT be labelled as executing bcc's full C frontend.

The `abstract-machine` feature exposes `pub mod abstract_machine`. The module
requires only std and builds on native and wasm32. `abstract_machine_wasm.rs`
wraps the safe Rust API; the engine defines no raw exports.

PUBLIC API:

  pub fn compile(source: &str) -> Result<Program, Diagnostic>;

No unsafe ABI in engine; wrapper can hold Session and return JSON bytes.

JSON schema v7 (v1 fields shown; later versions add the event, evaluation
and structure fields, objects' storage_duration "static", function, parameter
and literal, and the state's output and written; v5 adds the diagnostic kind
"constraint"; v6 adds objects' size in bytes, events' from_type and
result_type, and the event kinds "sizeof" and "arithmetic_conversion"; v7
adds the value kind "floating"):
  {schema_version:7, engine:"bounded-c-subset", step:number,
   status:"ready"|"running"|"finished"|"undefined_behavior"|"error"|"limit",
   source_range:{start:byteOffset,end:exclusiveByteOffset,line:oneBased,
                 column:oneBased,end_line:oneBased,end_column:oneBased},
   event:string, frames:[{id:number,function:string,depth:number}],
   objects:[{id:number,name:string,type:string,frame_id:number,
             size:number, storage_duration:"automatic",
             lifetime:"alive"|"ended",
             value:Value, literal:boolean}], pending_effects:[string],
   diagnostics:[Diagnostic], return_value:null|Value,
   output:string, written:number}
  output is everything written to standard output so far (bytes that are not
  UTF-8 become replacement characters in JSON; State::output keeps the
  bytes), written how many bytes at its end the last step wrote.
  Value = {kind:"indeterminate"} | {kind:"integer",value:number}
  An integer's value is exact in the JSON text, up to 18446744073709551615;
  a JavaScript number keeps only values below 2^53 exactly. Its type is the
  object's (type) or, in an event, result_type: "int", "unsigned long", ...
        | {kind:"floating",type:"float"|"double"|"long double",
           value:string,exact:string,bytes:[number]}
  A floating value's value is the shortest decimal that reads back as it
  ("0.1", "0.30000000000000004", "3.0", "inf", "-nan"), exact its exact
  decimal value ("0.1000000000000000055511151231257827021181583404541015625"),
  and bytes its encoding in memory, lowest address first (4, 8 or 16; a long
  double's six padding bytes after its ten are shown as 0).
        | {kind:"pointer",target:number|null,offset:number}
        | {kind:"array",elements:[Value]}
  Diagnostic = {kind:"unsupported"|"syntax"|"constraint"|"undefined_behavior"
                     |"indeterminate"|"limit",
                message:string,source_range:Range,citation:string|null}
  "constraint" is a compile-time violation of a C99 constraint, which every
  compiler must diagnose (5.1.1.3p1): the program is not valid C, as opposed
  to "unsupported", valid C outside the subset.
Pointer offsets are int elements, never host addresses. Object IDs never reused.
source_range is the next operation; event describes the last completed step.
An event's from_type and result_type are the arithmetic types a conversion,
a promotion or a converting store went from and to, a constant's or an
operator's result type, or null.
Trace JSON: {schema_version:7,source:string,structures:[...],states:[State,...]}.
Back restores a recorded complete machine state; forward replays existing states.

Subset: the standard integer types with bcc's x86-64 Linux widths: char
(plain char signed), signed char and unsigned char (8 bits), short and
unsigned short (16), int and unsigned int (32), long, unsigned long, long
long and unsigned long long (64), spelled with their specifiers in any order
(`long unsigned int`), and size_t (unsigned long) once <stdio.h> is
included; the real floating types float (IEEE 754 binary32), double
(binary64) and long double (the x87 80-bit extended format, in 16 bytes),
which C99 Annex F makes IEEE (F.2), as bcc defines __STDC_IEC_559__;
pointers to them all (and to their const versions), fixed arrays of
them, const objects and arrays of them, structures and pointers to them,
file-scope and block-scope static objects, named functions returning an
arithmetic type or a structure with named parameters of those types (and
pointers), prototypes declared before
their definitions, block locals/scopes, if/else, while, for, return,
assignments, arithmetic/comparisons, the shifts << and >>, sizeof (of an
expression or a type name), address/dereference/subscript/member, casts
between arithmetic types and between pointers that differ only in const,
prefix/postfix increment and the compound assignments += -= *= /= %= <<= >>=
as standalone statements, and one ++ or -- inside a controlling expression
(`k-- > 0`). Integer constants are decimal, with an optional u, l or ll
suffix, typed as 6.4.4.1p5 lists. Floating constants are decimal (`0.1`,
`.5`, `2.`, `1e-3`) or hexadecimal (`0x1.8p1`), with an optional f or l
suffix (6.4.4.2), at most 256 characters; one beyond its type's range is a
constraint diagnostic (6.4.4p2). Array and structure brace initialization; char arrays
also from a string literal, with or without a size. Character constants and
string literals with the simple, octal and hexadecimal escapes; adjacent
string literals are joined (translation phase 6). At file scope, `#include
<stdio.h>` and object-like `#define NAME replacement` whose replacement is one
decimal integer constant, floating constant, character constant or string
literal, each run by
the machine as one step of translation phase 4, and the calls printf, puts
and putchar. printf takes %d %i %u %x %c %s %% and %f %F %e %E %g %G %a %A
with the - and 0 flags, a decimal field width, a decimal precision and the
length modifiers hh, h, l, ll and z (L, and l, which changes nothing, for
the floating conversions). No other directive (function-like macros, #if,
#undef, ...), header or library function, no _Bool, complex types or void,
no octal or hexadecimal integer constants, no bitwise & | ^ ~, logical && ||
or ?:, no
malloc, function pointers, arbitrary declarators (const pointers `* const`,
const parameters and members), wide literals, or compound side-effect
expressions. Unsupported input is an explicit diagnostic, never scripted or
ignored.
Evaluation order: chosen left-to-right for side-effect-free operands; calls
are allowed as a whole scalar initializer/RHS/return/condition/expression
statement. Calls in array initializer lists and nested calls are rejected.
Assignments/increments nested in expressions are rejected to avoid claiming
unimplemented C99 sequencing checks, except one ++ or -- of a variable named
directly in a controlling expression that uses its name nowhere else and has
no *, [], -> or call, so that no access can be unsequenced with the update
(6.5p2); the update stores at once and yields the old (postfix) or new
(prefix) value. pending_effects describes the next store;
this prototype does not model deferred/unsequenced writes.

Bounds: source <=32 KiB; parser nesting <=64; code <=8192 operations;
runtime <=2048 steps, <=32 frames, <=128 total objects (string literals
included), <=512 scalar cells, <=1024 operands; a string literal holds <=511
characters (after joining), a library call <=16 arguments, a printf field
width and precision <=256 each, and
standard output <=4096 bytes; recorded states stop at an 8 MiB conservative
retention threshold (output included; plus one bounded terminal state and
vector capacity overhead). Limits are explicit terminal diagnostics, not UB or
silent truncation.

IMPLEMENTATION NOTES:
- Session snapshots retain the complete operand/call/scope/object state, rather
  than recomputing execution on back/forward. IDs are activation/allocation IDs.
- Indeterminate reads (including pointers whose targets have ended) stop with
  kind "indeterminate", status "error" and a verified rule. This is a
  conservative prototype policy, not a claim that every such read is UB.
- Integer arithmetic computes in the operator's type: the common type the
  usual arithmetic conversions choose, or for a shift the promoted left
  operand's type. A signed result outside its type stops (6.5p5); an
  unsigned one is reduced modulo 2^N and narrated as defined (6.2.5p9),
  with the exact result and the reduction (`2 - 3 is -1 ... -1 + 2^32 =
  4294967295`).
- Each operand of a type narrower than int is promoted in a step of its
  own (6.3.1.1p2). When a binary operator's promoted operands differ, a
  step per converting operand (event "arithmetic_conversion") says which
  converts and why: rank, the unsigned type's rank at least the signed
  one's, a wider signed type holding every unsigned value, or both
  converting to the unsigned type of the signed one's rank (6.3.1.8p1,
  6.3.1.1p1). A shift brings its operands to no common type (6.5.7p3).
- Conversion to an unsigned type reduces modulo 2^N (6.3.1.3p2), shown as
  arithmetic; to a signed type that cannot hold the value it wraps the same
  way, the implementation-defined result bcc and GCC give (6.3.1.3p3). A
  store, an initializer (static ones included), an argument, a return value
  and a cast convert this way, and the step that converts says so.
- Floating values are their encodings (Real), computed in software the same
  on every host: each + - * / forms its exact result with arbitrary-width
  integers and rounds it once to its type, to the nearest, ties to even
  (F.3, F.7.3); each type computes in itself (FLT_EVAL_METHOD 0). A
  constant becomes the nearest value of its type (6.4.4.2p3), and its step
  shows the exact value stored. The usual arithmetic conversions with a
  floating operand convert the other operand straight to the wider
  floating type, an integer without the integer promotions (6.3.1.8p1), a
  step per converting operand. Integer to floating is exact or rounded to
  the nearest (6.3.1.4p2); floating to integer truncates toward zero, and a
  value whose integral part does not fit (or an infinity or a NaN) stops as
  undefined (6.3.1.4p1; Annex F's F.4 would make it an unspecified value,
  but compilers optimize on 6.3.1.4). float to double and double to long
  double keep the value (6.3.1.5p1); narrowing rounds to the nearest, and
  beyond the range gives an infinity as Annex F defines (6.3.1.5p2). A store,
  an initializer (static ones included), an argument, a return value, a
  compound assignment and a cast convert this way. Division by zero gives an
  infinity, and 0/0 and other invalid operations the default NaN of x86-64,
  whose sign bit is set (glibc prints -nan), under Annex F; without it the
  division would be undefined (6.5.5p5). Comparisons see exact values; a
  NaN is unordered: every comparison with it is 0 except !=, and a NaN
  condition is true. % and the shifts need integer operands (constraint
  6.5.5p2, 6.5.7p2). A float passed through printf's ... is promoted to
  double in a step of its own (6.5.2.2p6).
- printf's floating conversions write the exact decimal (or hexadecimal)
  expansion of the value rounded to the precision, to the nearest with ties
  to even, as glibc 2.39 does: %f and %e with 6 digits by default, %g with
  trailing zeros removed, %a with glibc's leading digit (1 for a double, the
  top four bits of the 64-bit significand for a long double); inf, -inf,
  nan and -nan, upper case for %F %E %G %A, padded with spaces under the 0
  flag. With a floating conversion a precision keeps the 0 flag. %f, %e, %g
  and %a take a double (l changes nothing) and with L a long double; any
  other argument, and hh, h, ll or z before them, is undefined (7.19.6.1p7,
  p9).
- sizeof is one step (event "sizeof") yielding the size of its operand's
  type as an unsigned long; the operand is not evaluated and an array does
  not decay (6.5.3.4p2, p4; 6.3.2.1p3).
- UB checks: checked signed arithmetic in every signed type, division/
  remainder by zero and MIN / -1, a shift count that is negative or at
  least the promoted left operand's width (6.5.7p3), a left shift of a
  negative or overflowing signed value (6.5.7p4),
  invalid/null/one-past dereference, pointer arithmetic outside the target,
  a store into a string literal's array (6.4.5p6), and for the library calls
  a null pointer where a string is needed (7.1.4p1), a string with no null
  before the end of its array (7.1.1p1, 7.19.6.1p8), a conversion with no
  argument left (7.19.6.1p2), an argument whose type is not the one its
  conversion and length modifier name (nor that type's signed or unsigned
  counterpart with a value both hold, 6.2.5p9), a length modifier with %c,
  %s or %%, an invalid specification, the 0
  flag with %c or %s (7.19.6.1p6, p9), and a precision with %c (7.19.6.1p4);
  a store into an object defined const through an lvalue that is not, which
  only a cast that removed the const can form (6.7.3p5); a floating value
  converted to an integer type that cannot hold its integral part
  (6.3.1.4p1).
- Directives run before the static objects are created, one step each; the
  machine runs only `#include <stdio.h>`, which must come before the first
  call to printf, puts or putchar (7.1.2p4), and object-like `#define`. Every
  other directive, a #define with any other replacement list, and a directive
  inside a function, is rejected; the site then shows its "machine starts
  after the preprocessor" card. A redefinition with a different replacement
  is a constraint diagnostic (6.10.3p2); an identical one is a step that
  changes nothing.
- A #define replaces each later instance of its name before compilation
  (6.10.3p9), so the program the machine compiles never mentions it. Each
  operation that evaluates a replacement (a constant, a character constant,
  a string literal's array) is marked with its macro and narrated as the
  replacement standing in for the name, citing 6.10.3p9; a macro in an array
  size or a static initializer is noted on that declaration's step. The
  replacement is checked where it is defined.
- Adjacent string literals become one literal after escape replacement
  (5.1.1.2p1 item 6, 6.4.5p4), so "\x4" "1" is two characters: one static
  array named by the literals as written, separated by one space, whose
  creation step says they were joined.
- const objects: assignment, compound assignment, ++ and -- on a const object
  or through a pointer to const are constraint diagnostics (6.5.16p2,
  6.5.2.4p1, 6.5.3.1p1), and so is storing a pointer to const into a pointer
  to non-const (6.5.16.1p1). A const object's type is spelled "const int" or
  "const char". A const array decays to a pointer to const.
- A cast is one step converting its operand: a value the new integer type
  holds is kept (6.3.1.3p1); to an unsigned type it reduces modulo 2^N
  (6.3.1.3p2); to a signed type that cannot hold it, it wraps, the
  implementation-defined result bcc and GCC give (6.3.1.3p3); a cast to the
  operand's own type changes nothing (6.5.4p4); between pointers it adds or
  removes const; to or from a floating type it converts as the floating
  note above says. Casts to void, between integers and
  pointers, and between different pointer types are unsupported; a cast of
  or to a structure is a constraint diagnostic (6.5.4p2).
- `E1 op= E2` designates E1 in one step, evaluates E2, and in one step reads
  E1, applies op with the plain operator's checks and stores the result
  converted to E1's type (6.5.16.2p3); its operands follow 6.5.16.2p1-2.
- printf's length modifiers name the argument's type after the default
  argument promotions: hh and h an int, which is converted back to the
  (unsigned) char or short before printing, l and z a long or unsigned
  long, ll a long long (7.19.6.1p7). A char or short argument is promoted
  in a step of its own.
- printf precision is the minimum number of digits for %d %i %u %x (a zero
  with precision 0 writes nothing) and the maximum number of characters %s
  writes, which then needs no null within that many (7.19.6.1p4, p8); with
  a precision the 0 flag is ignored (7.19.6.1p6).
- Each string literal in the source is its own unnamed char array of static
  storage duration, named by its spelling, created before main in source
  order. A literal that initializes a char array names no object: its
  characters initialize the array in one step (6.7.8p14).
- A library call is one step: it reads its strings element by element with
  the ordinary lifetime, bounds and indeterminate checks, writes to standard
  output and returns what C says (printf the count written, putchar the
  character as an unsigned char, puts a nonnegative value: the count written,
  as glibc returns). A char passed through printf's `...` gets the default
  argument promotions as a step of its own. Valid printf specifications the
  machine does not model (*, length modifiers, other flags and conversions)
  stop as unsupported, not UB.
- &*p and &array[n] cancel indirection per C99 6.5.3.2p3, allowing formation
  of a one-past pointer without treating it as a read.
- Syntax, type and call-arity checks run for all parsed code, including dead
  branches. Unknown names/callees, incompatible pointer/int assignments,
  nested writes/calls, and unsupported preprocessing transformations fail.
  Constraint checks (const, compound-assignment operands, casts) run there
  too, so a program that breaks one never starts.
- Non-main fallthrough is conservatively unsupported even if a caller would
  discard the value. Main fallthrough returns zero. Array tails initialize zero.
- Pending effects describe the imminent store/increment; there is no deferred
  side-effect queue, exhaustive order exploration, or whole-C UB certification.
- No engine ABI exports; the wasm bridge wraps this safe API.
- Calls require the current function, an earlier definition or an earlier
  prototype (self-recursion works). Every declaration of a function must give
  it the same return and parameter types (6.7.5.3p15); a prototype with empty
  parentheses, a call to a function declared but never defined, and an
  unnamed parameter in a definition are rejected. A const char * may not be
  stored into a char *, and a char reached through one may not be modified.
- Standalone (*p)++/(*p)-- and ++*p/--*p update the pointed-to int. Bare *p++
  and *p-- are rejected as nested effects, preserving C postfix precedence.

Automatic lifetimes begin at declarations in this prototype. C99 fixed
automatic objects instead begin lifetime at block entry (6.2.4p5); initialization
happens when the declaration is reached. This approximation is visible in the UI.
