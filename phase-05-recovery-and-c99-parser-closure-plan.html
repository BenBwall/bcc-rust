Phase 05 · Final syntax-parser phase

Close the parser with evidence.

Audit the complete C99 grammar, track GCC/Clang front-end behavior without copying their bugs, repair the syntax and diagnostic seams, make recovery predictable, prove the translation floors, and expose a syntax tree that the next compiler phase can actually use.

Design direction One deep parser module

Small translation-unit interface. Private frames, recovery, arenas, scopes, and reducer machinery. Behavioral tests cross the same seam as future analysis.

02 / Objective

Parser-complete means complete syntax, not a complete compiler.

Phase 05 must deliver

  • Every meaningful strict-C99 grammar alternative and interaction evidenced.
  • Complete source-backed translation units behind typed handles.
  • Structured primary/related diagnostics with warning control and active production.
  • Nearest-seam recovery with caller delimiter and scope ownership preserved.
  • Every parser-relevant C99 minimum translation limit proven.
  • Version-pinned GCC/Clang observations classified against C99.
  • An opt-in, deterministic parser inspection view.

Keep outside the parser

  • Type compatibility, conversions, lvalues, layout, and linkage.
  • Constant evaluation and initializer current-object rules.
  • General label, jump, switch, loop, and return legality.
  • Vendor extensions and a generalized dialect plugin surface.
  • Exact compiler diagnostic wording, count, global order, or AST layout.
  • Drop-in CLI, ABI, object-file, assembly, and linking compatibility.
  • IR, optimization, and code generation.
  • Rewriting the dated root research reports as current documentation.
03 / Compatibility

Copy observable compiler behavior; let C99 break ties.

Phase 05 compatibility profile

  • One ordinary C99 profile comparable to -std=c99 -pedantic-errors.
  • GCC and Clang acceptance, severity, warning control, locations, and continuation are version-pinned evidence.
  • The reviewed C99 interpretation wins whenever the compilers disagree.
  • GNU grammar and other vendor extensions require a future explicit profile.

Deliberate freedom to do better

  • Use clearer prose, richer ranges, related notes, and explicit recovery data.
  • Do not clone compiler bugs, internal IDs, AST layout, exact multiplicity, or global diagnostic order.
  • Keep repository-reviewed fixture classifications authoritative when host compilers change.
  • Preserve existing early constraint checks provisionally without expanding semantic analysis.
Compatibility boundary: Phase 05 targets front-end source behavior. Full command-line, ABI, object-file, assembler, and linker drop-in compatibility remains a project-level direction.

05 / Gaps

The remaining work is concentrated in twelve closure risks.

P0 · Model

Storage absence is erased

DeclarationSpecifiers::new defaults to StorageClass::Auto. Later analysis cannot distinguish no specifier from explicit auto. Store presence explicitly.

P0 · Provenance

Identifiers have no source

Identifier carries only a string-cache ID. Give every declarator, tag, member, enum constant, label, and expression identifier its exact SourceVectors.

P0 · C99

Acceptance and lint are coupled

Repeated qualifiers and inline are valid C99. Always accept them; any quality warning must use a named suppressible group and remain independent of pedantic acceptance.

P0 · Handoff

A production todo! remains

map_preprocessor_token assumes unmatched token categories are unreachable. Make the phase-7 conversion exhaustive and nonpanicking.

P0 · Syntax

Invalid imaginary types look valid

Recognize _Imaginary as a keyword, diagnose it as non-C99 type syntax, and retain only invalid/recovered syntax - not normalized valid-looking type variants.

P0 · Interface

Only a raw arena dump is exposed

syntax_debug() is not a consumer interface. Add ordered translation-unit roots and checked typed syntax lookup.

P0 · Diagnostics

Messages carry hidden structure

Symbolic code, warning group, frame, expectation, found token, ranges/notes, recovery, and primary source must be fields. Deliver primary/related groups FIFO without global source sorting.

P0 · Recovery

Garbage becomes a fake declaration

Use ExternalDeclaration::Error when no meaningful syntax survives. Recovered declarations must retain a useful declaration tree.

P1 · Recovery

Policy is difficult to audit

Make grammar-independent synchronization table-driven, preserve named parser-aware hooks, and cover the complete parent/child boundary matrix.

P1 · Resources

Input scale reaches expect

Centralize checked growth, prove C99 floors, and diagnose configured or representational limits where reporting is possible. Do not promise recovery from process-wide OOM.

P1 · Quality

Evidence is sampled and unversioned

Migrate behavior tests to SyntaxTree; add exhaustive EOF, floors, properties, and a version-pinned GCC/Clang compatibility corpus with reviewed classifications.

P1 · Locality

One source file owns everything

Improve locality behind the same parser interface. The proposed private files are guidance, not a mandatory architecture or a reason to create shallow modules.

06 / Shape

A narrow parent module over local frame families.

src/translation_phases/
├── parsing.rs              # narrow seam + re-exports
└── parsing/
    ├── syntax.rs           # SyntaxTree + checked arenas
    ├── machine.rs          # cursor + driver protocol
    ├── scopes.rs           # typedef-visible scopes
    ├── recovery.rs         # policies + delimiter state
    ├── diagnostics.rs      # structured diagnostic data
    ├── inspection.rs       # stable tree formatter
    ├── frames.rs           # frame sum + dispatch
    ├── frames/
    │   ├── declarations.rs
    │   ├── declarators.rs
    │   ├── parameters.rs
    │   ├── tags.rs
    │   ├── functions.rs
    │   ├── statements.rs
    │   ├── expressions.rs
    │   ├── type_names.rs
    │   └── initializers.rs
    ├── tests.rs
    └── tests/              # grammar/recovery/eof/limits/...

Interface properties

  • ParsedTranslationUnit owns ordered external roots and SyntaxTree.
  • Typed handles and list slices are validated at construction.
  • Callers receive read-only lookup, not raw arena vectors.
  • Absent, missing, recovered, invalid, and error syntax remain distinct.
  • Tests and semantic analysis cross the same seam.
  • Private modules use pub(super) only where genuine sibling access exists.

Layout rule: this tree is a starting hypothesis. Combine, rename, or omit files when implementation evidence shows better locality; the exit gate is a narrow interface and reviewable behavior, not matching the diagram.

07 / Inventory

Replace the binary checklist reading with ownership.

Parser-supported

Recognized and linked to a positive complete-tree test.

Parser-diagnosed

Intentionally invalid syntax with a stable diagnostic and recovery test.

Upstream-owned

Initial processing, token recognition, preprocessing, or phase-7 conversion owns it.

Semantic-owned

Syntax and provenance are retained for a named later analysis.

Out of scope

An explicitly rejected extension or non-v0 feature.

Open

A concrete Phase 05 implementation or evidence gap.

08 / Sequence

Twelve gates on one closure path.

Rebuild the compliance inventory

Classify all 121 rows, link existing evidence, separate parser work from semantic and upstream ownership, and create the missing fixture manifest.

  • Record baseline and known optional-feature lint debt.
  • Record the C99 profile, normalized GCC/Clang flags, and observed versions.
  • Do not mark enum coverage as grammar proof.
ExitFinite reviewed Phase 05 scope; every row has an owner or concrete open task.

Add the translation-unit and syntax seam

Introduce ParsedTranslationUnit, ordered roots, typed lookup, and checked list slicing. Retain streaming as an adapter only.

  • Migrate CLI and a characterization set first.
  • Prevent caller-created invalid handles.
ExitA complete translation unit is usable without touching parser fields.

Improve internals for locality

Use the suggested file map as a hypothesis, then split or retain syntax, machine, recovery, diagnostics, frame families, and tests according to demonstrated locality.

  • Keep phase enums beside frame implementations.
  • Avoid traits and shallow files created only to match the plan.
ExitBehavior is unchanged, the interface stays narrow, and implementation locality is demonstrably better.

Repair syntax facts and provenance

Represent storage-class absence, source every identifier, remove valid-looking imaginary types, and distinguish absent/missing/recovered/invalid syntax.

  • Audit tags, labels, members, typedef names, and enumerators.
  • Audit composite operator and delimiter provenance.
Exitint x differs from auto int x; every name has exact source.

Close strict-C99 token and grammar handling

Remove the mapping todo!, cover every token category and digraph, run the C99 profile with extensions denied, and fix remaining grammar gaps.

  • Accept repeated qualifiers and inline; route any quality warning through a suppressible group.
  • Confirm the mandatory parameter typedef preference.
  • Reject vendor grammar without rejecting C99.
ExitAll syntax rows have direct evidence; no conforming construct is rejected and no handoff panic remains.

Structure and group diagnostics

Separate symbolic code, warning group, severity, frame, expectation, found token/EOF, primary source, ranges/notes, and recovery data.

  • Keep zero-width EOF anchors.
  • Deliver FIFO primary/related groups without globally sorting by source.
ExitConsumers never parse English text, and warnings can be controlled without changing C99 acceptance.

Harden cross-family recovery

Inventory every frame phase, table-drive common synchronization, isolate typedef/label/body hooks, implement root error nodes, and enforce cleanup.

  • Add the complete parent/child boundary matrix.
  • Add a test-only action/progress budget.
ExitMalformed children preserve the nearest legal following construct and leak no state.

Build grammar and compatibility evidence

Cover every meaningful normative alternative with concise trees; add ambiguity, handoff, extension-rejection, and version-pinned GCC/Clang fixtures.

  • Normalize dialect, pedantic, warning, target, and error-limit flags.
  • Classify differences against C99; repository review is authoritative.
ExitChecklist alternatives map to complete-tree assertions and every compiler difference is classified.

Exhaust EOF and malformed states

Generate token-boundary truncations and bounded source mutations with proptest; persist minimized failures as normal regressions.

  • Assert termination, diagnostic source, and clean machine state.
  • Add material recovery differences to the compatibility corpus without cloning exact prose/count/order.
ExitEvery EOF-capable phase is tested and malformed input cannot reach invariant panics in the tested domain.

Prove floors and diagnose resources

Centralize checked storage growth and test all remaining C99 minima: mixed derivations, identifiers, cases, members, enumerators, and nested tags.

  • Test floor - 1, floor, floor + 1, and deeper stress where applicable.
  • Diagnose configured/representational limits where reporting is possible; do not promise process-wide OOM recovery.
ExitEvery parser-relevant §5.2.4.1 floor passes and catchable excess yields a stable diagnostic.

Add opt-in syntax inspection

Render source-ordered roots, readable identifier spellings, child roles, operators, and recovered/error markers through SyntaxTree.

  • Keep tree inspection and raw arenas under separate explicit options.
  • Golden-test valid, macro, and recovered output.
ExitNormal CLI behavior remains compiler-like; requested inspection explains syntax rather than storage layout.

Close documentation and gates

Update the checklist, roadmap, glossary, README, compatibility profile, and differential-corpus policy only after implementation evidence is green.

  • Run all canonical checks and git diff --check.
  • Record later semantic work; do not rewrite historical reports.
ExitThe repository can accurately claim C99 syntax-parser completion without claiming full compiler compatibility.
