02 / Decision

Replace control flow; preserve the compiler seam.

The migration keeps parser-facing tokens, source vectors, arenas, diagnostics, and the existing TranslationPhase integration where they remain sound. It does not repair the old parser first: recursive grammar paths are replaced in slices, then deleted.

Target module

One deep ParserMachine module.

Its external interface stays small: construct it with the preprocessor, then pull external declarations through TranslationPhase::next_item. The control stack, cursor, frames, scope transitions, recovery, and syntax stores remain implementation details.

  • One heap-backed control stack.
  • Specialized frame state machines.
  • No recursive parser calls.
  • Owned actions cross the driver seam.
  • Caller delimiters remain unconsumed.
  • Syntax parsing stops before semantics.
  • Malformed input never panics.
  • No long-lived second parser.
  • ISO C99 only for v0; no extensions.

04 / Architecture

A small interface over a deep implementation.

The parser is entirely in-process, so no adapter is needed at its external seam. The expression reducer earns an internal seam because two real adapters use it: preprocessing evaluation and language-AST construction.

Input ownership

Buffered token cursor

Wraps Preprocessor and replaces pending_token.

  • One explicit lookahead
  • Consume or reprocess
  • EOF is a real event
  • Source vectors retained
→
Deep module

ParserMachine

Owns Vec<ParseFrame>, typed results, scope state, syntax stores, and recovery state.

  • Step top frame
  • Apply owned action
  • Resume parent with value
  • Yield external declaration
↔
State + output

Syntax stores & scopes

Typed handles preserve ownership while frames carry only partial grammar state.

  • Expressions and lists
  • Declarations and types
  • Statements and errors
  • Scoped name classes
One control stack does not mean one operator stack. Expression frames use the Double-E reducer. Declarators may use a constructor reducer only if it reduces their interface. Keyword-led declarations and statements use local phase enums.
05 / Interface

Derive grammar shape; define only the machine protocol.

The C99 standard determines what the parser must recognize. The engineering work here is the owned action protocol: the driver never keeps a mutable frame borrow while mutating the stack, token cursor, arenas, or scope state.

Proposed shape · names are commitments, fields are design inputs
struct ParserMachine {
    cursor: TokenCursor,
    frames: Vec<ParseFrame>,
    returned: Option<ParseValue>,
    syntax: SyntaxStore,
    scopes: ScopeStack,
    recovery: RecoveryState,
}

enum ParseAction {
    Consume,
    Push(ParseFrame),
    Reduce(ParseValue),
    Reprocess,
    Recover(SynchronizationSet),
}

enum ParseValue {
    Expression(ExpressionIndex),
    Statement(StatementIndex),
    Declaration(DeclarationIndex),
    Declarator(Declarator),
    TypeName(TypeNameIndex),
    Initializer(InitializerIndex),
    ExternalDeclaration(ExternalDeclaration),
    // Add list values only when a parent truly needs them.
}

impl TranslationPhase for ParserMachine {
    type Item = ExternalDeclaration;
    // next_item drives frames until one item or EOF.
}
Protocol invariants
  • Exactly one frame owns each expected delimiter.
  • Push does not consume the child’s first token.
  • Reduce pops one child and stores one typed result.
  • Reprocess cannot loop without a state change.
  • Parents reject unexpected ParseValue variants as internal invariant errors.
  • Recover identifies both a synchronization set and a legal unwind target.
  • Frame phase enums stay private to their frame family.
  • Tests and callers cross the same parser interface.

Phase01Reducer

Extract and harden the shared precedence reducer.

Create a real internal seam with two adapters while preserving preprocessing behavior.

Change

  • Extract operator metadata and stack reduction mechanics.
  • Keep values and diagnostics dialect-specific.
  • Add a crate-private last_entry(&mut Vec<T>) -> Option<LastEntry<'_, T>> utility whose entry can inspect, mutate, replace, or remove the final element.
  • Represent ? as an unmatched question marker and a matched ?: as a completed ternary operator.
  • When reading :, reduce operators through the middle expression, stop at the nearest unmatched ? inside the current parenthesis group, and use last_entry to replace that marker in place.
  • Represent grouping and comma context explicitly.
  • Carry a small typed compiler configuration for the selected C standard and extension policy; use operand liveness to diagnose only evaluated preprocessor comma extensions in strict C99.
  • Bubble structured preprocessor diagnostics through a mixed token/error iterator; keep formatting and printing at the outer executable boundary.
  • Replace user-input assertions with recoverable errors.

Prove

  • last_entry returns None for an empty vector and changes only the final slot for mutation, replacement, and removal.
  • Existing preprocessor behavior remains green.
  • 1 ? 0 ? 2 : 3 : 4 reduces the inner conditional first and produces 3.
  • Both middle-nested and right-nested ternary shapes reduce correctly.
  • Grouped comma differs from call separators.
  • Default extension mode reduces preprocessor comma to its right operand; strict C99 diagnoses evaluated comma but not comma confined to a short-circuited operand.
  • A diagnostic produced alongside a token is yielded first without invalidating either item's source vectors.
  • Missing operands never panic.
  • Equal-precedence associativity table is exhaustive.
Ternary correction. Operand-stack order is already correct. The defect is loss of ?/: pairing: the current colon operator reduces nothing, so a later ternary reduction takes whichever three operands happen to be on top. The new flow leaves ? as a blocking marker; : closes the nearest marker without crossing (, converts that vector slot to a completed conditional through last_entry, and lets the normal Double-E reduction pop condition, middle, and final operands. This is ternary support inside the shared reducer, not separate three-part parser syntax.
Comma boundary. The local Double-E demo remains intentionally smaller: commas separate call arguments, while grouped comma expressions are rejected. The future C language ExpressionFrame must distinguish those separators from BinaryOperator::Comma. The preprocessor reducer parses comma for compatibility, carries whether it is evaluated through short-circuit and conditional selection, and applies the configured extension policy only to evaluated comma.
ASAP implementation slice. Hand off phase-01a-conditional-expression-foundations-agent-brief.md. This 2–4 day slice adds the vector guard, fixes ternary pairing in bcc-rust and the Double-E demo, and rewrites the old language parser's expression model for C99 source mapping, index lists, and member access.

07 / File map

Split for locality, not for more interface.

10 / Cutover

Replace, verify, delete.

The broken legacy parser is a source of grammar knowledge, not a second implementation to maintain. Git already preserves its history.

Migration rule

For every grammar family

  1. Add interface-level characterization cases.
  2. Implement the corresponding frame phases.
  3. Switch the parent frame to the new child.
  4. Run the family gate and all prior gates.
  5. Delete the replaced recursive methods and stale tests.
Rejected approach

Do not create a permanent parallel parser

  • No long-lived feature flag selecting old versus new.
  • No frame methods that call back into recursive grammar methods.
  • No public frame constructors for tests.
  • No semantic type checking inside syntax frames.
  • No shared reducer that exposes preprocessor-specific types.

11 / Done means

Completion requires evidence, not enum coverage.

The parser is complete for this migration only when the entire syntax path satisfies these observable conditions.

No recursive parser calls

Every nested grammar construct is represented by a heap-backed frame.

Deterministic token ownership

Trace tests identify which frame consumes every token and delimiter.

Complete C99 operator evidence

Golden AST cases cover precedence, associativity, postfix chains, and comma roles.

Scope-correct ambiguity

Typedef shadowing drives declarations, casts, sizeof, and block-item choices.

Whole translation units parse

Functions, declarations, statements, initializers, labels, and nested blocks compose.

Caller delimiters survive

Child frames stop before every caller-owned terminator at every nesting level.

Malformed input never panics

Diagnostics are bounded, source-rich, and followed by legal recovery or unwind.

One reducer, two adapters

Preprocessor evaluation and language AST construction share precedence mechanics only.

Memory follows active nesting

One parser implementation remains
