Implementation depth report

The declaration machinery is real. The parser is not yet complete.

The parser contains substantial C99 type-specifier and declarator logic, plus a broad AST design. But the high-leverage grammar layers—expressions, statements, initializers, function definitions, and a complete external-declaration path—are missing or stop mid-implementation.

Why method count is misleading

  • 27 of 30 parser methods contain non-placeholder bodies.
  • Much of that code serves one difficult but limited area: declaration specifiers and declarators.
  • parse_expression and parse_statement are tiny stubs for enormous grammar subtrees.
  • The core declaration/function-definition routine ends after only the no-declarator case.
  • AST variants describe intended support; they do not consume tokens or produce nodes.
  • The current module has 14 compile errors, so none of the implemented-looking paths are executable at HEAD.

05 / DESIGN VS EXECUTION

The intended AST is ahead of the parser

Strong design signals

  • Broad type vocabularyPrimitive combinations include signedness, short/long/long long, floating, complex, imaginary, structs/unions, enums, and typedef names.
  • Compact arena-oriented representationIndex wrappers and VectorSlice references suggest deliberate memory locality and stable node references.
  • Useful statement taxonomyThe model anticipates loops, conditionals, jumps, labels, cases, declarations in for, and null statements.
  • Useful expression taxonomyMost common unary, binary, assignment, call, subscript, cast, literal, and sizeof forms have a planned representation.
  • Recovery-aware diagnosticsThirty-eight error variants distinguish structural failures and several recoverable duplicate/conflict cases.

Model gaps that expose unfinished design

  • TypeName is referenced but absentThis blocks compound literals, casts, sizeof(type), and the parser’s own storage vector.
  • No function-definition nodeOnly FunctionDefinitionIndex exists; there is no structure describing a function’s specifiers, declarator, declarations, or body.
  • Declaration arenas are missingCode uses self.declarations and self.function_definitions, but neither field exists on Parser.
  • Name maps never changeTypedef/struct/enum recognition cannot become correct without binding and scope updates.
  • No member-access representation is obviousThe expression enums include subscript and call but no explicit . or -> operator/node.

    Primary/postfix → unary/cast → multiplicative through logical → conditional → assignment → comma. Add explicit member access and constant-expression validation.
