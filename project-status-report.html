02 / VERDICT

The current build is the gating issue

Executive assessment

The project demonstrates real compiler-front-end engineering: source tracking, tokenization, macro expansion, conditional preprocessing, diagnostics, parsing data structures, and custom allocation utilities. However, the checked-in parser is internally inconsistent and the public CLI never advances beyond preprocessing. No backend or code generation path is present.

04 / CAPABILITY

What is already there—and what is not

Implemented evidence

  • A four-module translation pipeline: initial processing, tokenizer, preprocessor, and parser.
  • Macro expansion support exercised by manual fixtures for define, paste, triple-paste, stringify, variadics, and conditionals.
  • Quoted/system include paths plus CPATH and C_INCLUDE_PATH integration.
  • Structured diagnostics with severity, file indexes, source positions, and source vectors.
  • Token support for identifiers, keywords, operators, strings, characters, integers, and floats.
  • Performance-oriented internals: string cache, deduplicating arena, shared storage, compact queues, and vector slices.
  • A Criterion benchmark concept for preprocessing one million generated declarations.

Material gaps

  • The default library does not compile, so the CLI cannot currently run.
  • The CLI is a verbose token dump and does not invoke the parser or produce compiler artifacts.
  • Parser routines for statements, expressions, and assignment expressions remain todo!().
  • An additional preprocessing branch also contains a runtime todo!().
  • No unit, integration, or conformance tests are wired into Cargo; the C files are manual fixtures only.
  • README.md and LICENSE are empty, and no CI configuration is tracked.
  • No backend or end-to-end C compilation workflow exists in the repository.

07 / NEXT

Recommended recovery sequence

  1. Restore a green default build

    Reconcile parser storage/types, error variants, callback signatures, and return paths. Make cargo check the first non-negotiable gate.

    Immediate
  2. Freeze and test the preprocessor boundary

    Turn the 14 C fixtures into integration tests with expected token or diagnostic snapshots. Add focused unit tests around macro expansion and source mapping.

    High value
  3. Define the parser’s minimum complete slice

    Choose a small C subset, implement expressions/statements without placeholders, and expose a parse path from the CLI before widening grammar coverage.

    Core work
  4. Repair engineering gates

    Fix benchmark feature compilation, lint spellings, MinGW long-double warnings, and add CI for check, test, nightly fmt, and Clippy.

    Short
  5. Make project intent legible

    Document supported/unsupported C99 features, toolchain requirements, usage, roadmap, fixture semantics, and supply an actual license.

    Short
  6. Decide what “compiler” means for v0.1

    Set an explicit milestone: front-end/tokenizer, AST-producing parser, or executable-producing compiler. Backend scope is currently absent and will dominate the path to C99 compliance.
